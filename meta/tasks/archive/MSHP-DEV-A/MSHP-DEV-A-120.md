# MSHP-DEV-A-120 — Synthesize developer annexation roadmap

## Description

Combine the editor/IDE, runtime/version-management, and runtime-package-manager investigations into the next evidence-based Machine-Soul implementation roadmap.

## Requirements

- Consume the VS Code, JetBrains/Toolbox, runtime/version-management, and package-manager synthesis outputs.
- Identify implementation work that is useful now versus work blocked only on maintainer-selected assimilation content.
- Keep installation-only annexation valid for subjects such as runtimes that may have no useful assimilation directives.
- Identify reusable plugin/extension inventory concepts only if VS Code/JetBrains evidence justifies them.
- Create bounded implementation tasks with clear dependencies/validation for the most useful near-term capabilities.
- Do not force all developer tooling under one generic abstraction.
- Update MSHP-DEV-ENV with implemented/planned coverage and deliberate deferred gaps.
- Coordinate with MSHP-WIN-CONFIG where VS Code/JetBrains configuration findings overlap, without duplicating ownership.

## Constraints / non-goals

- Do not implement the newly created roadmap tasks during synthesis.
- Do not invent maintainer preferences/configuration content.
- Do not create zombie tasks merely to represent possible future runtimes/IDEs/package managers.
- Do not close MSHP-DEV-ENV simply because one implementation phase is planned.

## Acceptance criteria

- A concrete roadmap exists and every implementation task is traceable to investigation evidence.
- Install-only and config-capable annexation subjects are both represented correctly.
- Deferred ecosystems/config choices remain structured initiative gaps rather than incomplete tasks.
- No duplicate source-of-truth is created with MSHP-WIN-CONFIG.

## Validation

- Trace every proposed task to one or more investigation findings.
- Verify dependency and Dispatch eligibility rules.
- Review initiative/task/reminder boundaries before completion.
