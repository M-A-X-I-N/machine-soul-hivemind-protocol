# Discovery implementation shape

DISC-A established two implementation tracks over one shared evidence/assessment model.

Installation discovery is mechanism/platform-oriented: shared declaration/engine, then Linux, native Windows, and Windows POSIX-environment backends.

Effective configuration verification is operation/strategy-oriented: first-class verify_config plumbing, then shell startup tracing, native resolution/application probes, and OMP consumer selection.

The tracks are intentionally not forced into matching task shapes. They converge only at a read-only orchestrator status surface after each underlying atomic operation is proven.

The detailed task roadmap is MSHP-DISC-B. Raw investigation traceability remains in the DISC-A workspace until archival.


## Implemented convergence — MSHP-DISC-B

The DISC-B roadmap is now implemented end to end.

- Installation discovery uses shared typed assessments plus Linux, native Windows, and Windows POSIX-environment backends.
- `verify_config` is a first-class atomic operation with shell, native-application, and Oh My Posh verification strategies.
- The broad manager `status` workflow composes `check_installed`, `check_config`, and `verify_config` without collapsing them into one score or semantic result.
- Human presentation summarizes each dimension; JSON preserves the original atomic results and complete assessment data.
- Representative mixed scenarios are contract-tested: foreign-but-effective, applied-but-ineffective, staged config with absent install, ambiguous installation, and unverifiable runtime.
- Raw DISC-A workspace material is historical traceability now; continuing architecture should rely on the promoted docs and agent notes unless investigating why a decision was made.

Installation takeover remains a separate reminder and was not implemented by DISC-B.
